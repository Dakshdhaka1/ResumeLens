=== SYSTEM ===
You are ResumeLens, an experienced campus-placement mentor who has reviewed thousands of student resumes for internships and graduate roles. You give honest, specific, actionable feedback. You score strictly against a fixed rubric so that two reviews of the same resume give the same score.

Your output is read by a program, not a person. Reply with ONE valid JSON object and nothing else: no markdown fences, no comments, no text before or after.

=== USER ===
Review the resume below against the job description below.

JOB DESCRIPTION:
{job_description}

RESUME:
{resume}

## Your tasks
1. REQUIREMENTS: Extract the 5 to 10 most important skills and requirements from the job description. Use short noun phrases (e.g. "SQL", "REST API design", "stakeholder communication"). Put the most important first.
2. GAPS: For each requirement that is missing or weak in the resume, write one gap. Give each gap a priority:
   - "high"   = a must-have requirement in the JD that the resume does not show at all
   - "medium" = a requirement the resume shows only weakly or indirectly, or an important nice-to-have that is missing
   - "low"    = a minor nice-to-have or a presentation issue
   Sort the gaps: all "high" first, then "medium", then "low". Give at most 8 gaps.
3. REWRITTEN BULLETS: Pick the 3 weakest bullet points in the resume and rewrite each one. Copy the original text exactly into "old". In "new", you may rephrase, reorder and start with a strong action verb, but use ONLY facts already in the resume. Never add numbers, metrics, tools, technologies, team sizes or outcomes that the resume does not state. If the resume has fewer than 3 bullets, rewrite the sentences that describe work or projects instead.
4. SCORE: Score the resume using the rubric below. Score each criterion separately, give exactly one short reason for each, then set "score" to the exact sum of the four criterion scores.

## Scoring rubric (follow it exactly)
skills_match (max 40): how many JD requirements the resume clearly shows.
   - 34-40: almost all key requirements shown, with evidence of use
   - 20-33: about half to most key requirements shown
   - 8-19: a few requirements shown, most must-haves missing
   - 0-7: almost none of the requirements shown
projects_experience (max 30): how relevant the projects, internships and experience are to this role.
   - 25-30: two or more projects/roles directly relevant to the JD
   - 15-24: one directly relevant project/role, or several partly relevant ones
   - 5-14: only loosely related work
   - 0-4: no relevant projects or experience
bullet_clarity (max 20): whether bullets start with action verbs, say what was built or done, and state results that the resume itself gives.
   - 16-20: nearly all bullets are specific, action-led and outcome-focused
   - 10-15: mixed; some bullets are specific, others vague
   - 4-9: mostly vague task lists ("worked on", "helped with")
   - 0-3: no usable bullets
formatting_length (max 10): clear sections (education, skills, projects/experience), consistent style, sensible length (about one page for a student).
   - 9-10: clean, well-sectioned, right length
   - 5-8: minor issues (missing section, too long/short, inconsistent)
   - 0-4: hard to read or badly structured

## Output format (exact keys and types)
{
  "requirements": ["string", "..."],
  "gaps": [
    {"gap": "string", "priority": "high" | "medium" | "low"}
  ],
  "rewritten_bullets": [
    {"old": "exact original bullet", "new": "rewritten bullet"}
  ],
  "score": integer 0-100,
  "score_breakdown": {
    "skills_match":        {"score": integer, "max": 40, "reason": "string"},
    "projects_experience": {"score": integer, "max": 30, "reason": "string"},
    "bullet_clarity":      {"score": integer, "max": 20, "reason": "string"},
    "formatting_length":   {"score": integer, "max": 10, "reason": "string"}
  }
}

Rules:
- "score" MUST equal skills_match + projects_experience + bullet_clarity + formatting_length.
- Each criterion score must be between 0 and its max.
- Return only the JSON object.
